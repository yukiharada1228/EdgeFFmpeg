# aformat sample-format constraint

The bounded linear filter compiler accepts `aformat` (no constraints), `aformat=sample_fmts=<format>`, alias `f=<format>` and the first positional format. Supported singleton formats are packed u8/s16/s32/flt/dbl and planar u8p/s16p/s32p/fltp/dblp. Preference lists, sample-rate constraints and channel-layout constraints remain unsupported and fail explicitly. This is partial aformat compatibility.

A specified format participates in forward format negotiation and automatic rate-boundary placement. Fixed volume followed by a singleton integer aformat resolves to that precision, even if the encoder uses a different format. A floating constraint selects the existing signed32 intermediate for preceding fixed volume. Aformat itself retains rate, channels, sample count and PTS; converting output owns its plane. The no-constraint form passes metadata/data through without a format conversion.

Aformat works with scoped volume, asetrate and asetnsamples chains and CLI output -ar. Automatic format/rate conversion executes at the negotiated boundary. Input/output trim and FIFO padding follow the existing ordered count model. Float-to-integer rounding keeps the existing scalar/finite conversion restrictions, including CLI -cpuflags 0 where required. Declaring a format does not enable arbitrary resampler settings, complex graphs or channel rematrix combined with rate conversion.

Each constrained aformat reserves two payload handoff slots in the PCM static planner, and its target width contributes to frame-size budgeting. This remains a payload estimate, not observed total isolate memory.

Evidence includes 96 mixed-format/rate cases (four source representations, eight chains and three output precisions) with exact counts and normalized sample tolerances of 1e-6 for floating output or 1e-6 plus one signed16 LSB for signed16 output. Fifty unchanged-rate cases compare whole framecrc text byte for byte across five input formats, five packed constraints and optional fixed volume, followed by FIFO padding. Unit tests cover syntax restrictions, widths, scalar rounding gates, rate-boundary planning, bigint PTS, independent ownership and allocation limits. Local workerd checks aformat before default FIR conversion and FIFO output. Full error/negotiation compatibility, general numeric domains and production Workers conformance remain unverified.

## CLI planar constraints

Planar singleton constraints are now connected to CLI execution, FIFO, linear/G.711 encoding, scoped rematrix and automatic rate conversion. Filter format metadata tracks packing separately from numeric precision. Constant volume currently returns packed processing output; explicit later planar aformat repacks as requested. Resampler internal precision selection ignores packing while boundary placement retains it, because a remaining packing conversion at the encoder can affect where native rate conversion occurs.

Output trim now slices every plane at the same sample indices using that plane's sample stride. This is necessary after planar FIFO or a negotiated planar resampling boundary. Aggregate width/buffer reservations continue to cover all channels. The encoder converts planar data to its supported wire representation; no new planar raw container format is implied.

Additional CLI evidence covers 168 rate-changing cases (four source representations, seven planar/mixed chains, mono/stereo and three output precisions) under input/output timing. Counts match exactly; normalized sample error is <= 1e-6 for floating outputs or <= 1e-6 plus one signed16 LSB for signed16. Fifty unchanged-rate cases compare whole framecrc text byte for byte across planar constraints, fixed volume and FIFO. Workerd verifies the packing-dependent rate placement: a dblp constraint followed by seven-sample padding and 8000-to-16001 conversion yields 141 samples, versus 133 for the packed dbl constraint. General preference lists, rate/layout constraints, complex graphs, non-default resamplers and combined rate/channel conversion remain incomplete.
