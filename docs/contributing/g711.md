# Partial G.711 A-law and mu-law support

`@edge-ffmpeg/avcodec` exports `decodeG711`, `encodeG711`, `isG711Codec` and the
G711Codec/Format/Options types. The shared PcmCodec type and decodePcm/encodePcm
entry points also accept pcm_alaw and pcm_mulaw. Companded data has one code byte
per channel/sample and expands to owned packed signed16 frames. Encoded packets
own their bytes, preserve sample counts, and rescale bigint PTS to sample time.

The independent decoder reconstructs segmented logarithmic magnitudes. The
encoder matches the fixed native signed16 profile: discard two low input bits
with arithmetic shifting, then select the nearest reconstruction magnitude,
with midpoint ties choosing the larger magnitude. No FFmpeg source or native
process is used by the runtime implementation. Scalar cross-format input uses
the existing finite PCM conversion profile; CLI float-to-integer transitions
require -cpuflags 0.

Companding is lossy. In particular, both mu-law zero codes decode to zero, and
re-encoding chooses the canonical positive zero code. Stream copy preserves the
original bytes. A-law reconstruction has no exact zero value. Resampling,
channel remix and general compressed-codec delay/flush behavior are not added.

## CLI and storage

Raw `-f alaw` and `-f mulaw` use matching default encoders. Raw declaration defaults
remain 44100 Hz and one channel, as in the pinned FFmpeg; declare -ar 8000 for
8 kHz audio. WAV defaults to linear pcm_s16le unless a codec is selected.

```sh
npm run ffmpeg -- --root ./media -- -f s16le -ar 8000 -ac 1 -i /input.raw -c:a pcm_mulaw /voice.wav
npm run ffmpeg -- --root ./media -- -i /voice.wav -f s16le /decoded.raw
```

The finite WAV reader accepts tag 6/7, eight coded bits and aligned sample data,
including the recognized extensible subtype. The writer emits appropriate
format metadata, fact sample counts and odd-byte RIFF padding. Native FFmpeg can
read generated mono/stereo/three-channel files, and the reader also consumes
native-generated WAV. Header byte identity, malformed fact semantics, unknown
length streams and RF64 remain outside this profile.

The existing sequential frontend supports copy, codec conversion, filters,
scoped time and packet-count limits, framecrc, staged output and payload memory
planning. Plans account for one-byte coded and two-byte decoded samples.

## Evidence

Every 8-bit decoder codeword and every signed16 encoder input is compared byte
for byte with the pinned native build under default and scalar CPU dispatch.
`compat/behavior-specs/g711-domains.json` locks the native output hashes and
upstream commit for these generated domains. Workerd independently computes
both complete domains and matches those hashes; a native differential test
refreshes their provenance by comparing the locked values against the oracle.

The CLI comparison covers an eight-by-eight linear/companded format matrix,
G.711 copy/filtered framecrc timing, and native/Edge WAV interoperability for
one through three channels. Unit tests cover plane offsets, bigint PTS, ownership,
mu-law zero canonicalization, invalid alignment/planes/budgets and cancellation.
These are scoped tests; full feature/CLI/runtime conformance remains uncertified.

## Planar input

The encoder accepts planar frames through scalar conversion. Native s16p frames are read directly in channel order without a packed scratch buffer. As with packed signed16 input, the output-only allocation budget can equal one byte per coded sample; other precision inputs require the converter's signed16 intermediate budget. Input planes must match channels and samples exactly. Full signed16 mono/stereo/six-channel native comparisons, subview/ownership/invalid-plane unit checks and local workerd evidence are covered by [planar audio](planar-audio.md).
