# Finite audio padding core

`@edge-ffmpeg/avfilter` exports `padAudio(frames, options)` and AudioPadError. Options require exactly one finite mode: `padSamples` (additional count), `wholeSamples` (minimum total count), `padDurationMicros` (additional duration) or `wholeDurationMicros` (minimum duration), all bigint, plus `maxFrameBytes`; optional packetSamples defaults to 4096 and cancellation uses AbortSignal. The finite count must fit nonnegative signed64 and packetSamples is a positive signed32 integer. This is a standalone streaming API. The finite CLI parser and original apad FATE execution are now connected as described below.

All five packed and planar numeric formats are accepted. Stable rate, channels, layout and sample format plus contiguous sample-aligned timestamps are required. Unknown PTS must remain consistently unknown. Each plane is validated, including sparse/misaligned channels. Input and generated output frame limits use aggregate bytes across all planes. For a fixed additional count or duration, the largest required silence packet is checked before yielding the first input frame. Minimum-total modes check the actual deficit after EOF; finite CLI planning preflights the known deficit before output creation.

Input frames are yielded unchanged with original ownership and packet boundaries. After EOF, the finite tail emits new independently owned packets of min(packetSamples, remaining) samples. Unsigned8 packed/planar silence is 128 and all other supported formats use zero. Planar output has disjoint channel views in one new allocation. Tail PTS advances from the first sample origin plus the total input and padded samples using bigint. No full-stream buffer or silence array proportional to total pad length is allocated. Consumer-held input/output, view objects and runtime overhead are outside maxFrameBytes.

Zero padding yields the validated input without a tail. Without a configured format, empty input produces no output. The optional emptyInput format/rate/layout/PTS descriptor allows finite silence after an empty configured stream, without a payload allocation for the descriptor. Input discontinuity, malformed dimensions or excessive packet size fail explicitly. Cancellation is checked before input and allocation, and backpressure/early return propagate to upstream iteration. Infinite padding, timeline enable and general native command semantics are not implemented by this API.

Ninety native cases cover five precisions, mono/stereo/six channels, packed/planar layout and 0/1/10 added samples. Native graphs use explicit input format and five-sample input reframing, then seven-sample padding packets. Every packet's PTS, duration, coded signed16 byte count and framecrc checksum match. Unit evidence covers bigint origins, owned silence, unsigned channel values, exact finite tails, aggregate preflight, sparse planes, discontinuity, cancellation and early return. Workerd exercises a six-byte planar budget. These standalone comparisons are separate from the official FATE profile described below.

## Finite CLI apad and official FATE

The filter compiler accepts exactly one finite `pad_len`/`whole_len` sample count or `pad_dur`/`whole_dur` duration, and optional positive signed32 `packet_size` (default 4096). The first positional option is packet_size, matching native option order. A finite length is required and specifying both is rejected. Infinite/default padding and timeline enable remain unsupported. Finite CLI rate-conversion composition is supported as described below; scoped native resampler packet schedules are described in [resampling](resampling.md#semantic-resampler-packet-schedules). Scoped output frame limits use the finite packet schedules described below. Input-side trim, scoped metadata/volume/aformat/FIFO chains, nested finite padding and existing raw/container outputs are supported. File-backed CLI graphs provide configured format metadata even when input or an intermediate resampler emits no frames.

The planner tracks finite packet sections as (sample count, packet span), rather than assuming one uniform packet size. Appended silence adds a new section; subsequent asetnsamples replaces sections with its new framing. Framecrc consumes these schedules in constant payload memory while physical reads/encoded chunks can have arbitrary smaller sizes. Schedules are bounded in section count, validated against the exact total and copied before asynchronous output. Thus a partial final input packet is not merged with the first silence packet. Padding frame reservations use min(pad_len, packet_size) and count additional output handoff buffers.

Sixty CLI cases compare complete native framecrc output across three input precisions, mono/stereo, two physical I/O budgets and five FIFO/planar/nested-padding/fixed-volume chains. Section validation, finite parser/planner and original command projection have unit tests; workerd executes finite raw-output padding.

The reviewed fate-filter-apad profile runs the original pinned native Make target with its generated 44100 Hz stereo WAV. Generated input and relevant upstream helper/definition/reference sources are hash-locked. Edge executes the same media arguments projected into the VFS, and its entire framecrc must match both native and the checked-in upstream reference, including the final 2456-sample input packet followed by a separate ten-sample silence packet. The reviewed executed FATE set now contains five cases. This does not certify full apad semantics or general FFmpeg compatibility.

## Minimum total sample count

`wholeSamples` in the library and `whole_len` in the CLI append max(target-inputSamples, 0) silence samples. The target concerns sample count, independent of the absolute PTS origin. Input already at/above target is passed through without allocating silence; empty input follows the configured-format rule above. The standalone streaming API determines the exact deficit after EOF and then checks the actual largest silence packet against its budget. Unlike fixed additional padding, it cannot know the deficit before consuming input.

For finite file-backed CLI planning, `requiredBufferSamples(inputSamples)` propagates known counts through each FIFO/padding stage and returns only actual required frame reservations. Thus a 4096-sample default packet_size does not require a 4096-sample allocation when the deficit is two or zero. The static maximum property remains available as a conservative potential upper bound. Packet sections and total output counts use the same deficit calculation.

Ninety-six additional native CLI cases cover targets below/equal/above input, zero target, FIFO before/after padding, planar constraints, nested whole/additional padding, mono/stereo, three source precisions and two physical I/O budgets. Whole framecrc bytes match. Unit tests verify exact section/count/buffer planning and CLI progress with an eight-byte buffer for both zero and two added samples; workerd verifies a minimum-five-sample output. Other apad scope restrictions above remain in force, and the reviewed original FATE set remains five cases.

## Duration-based finite padding

The CLI accepts finite nonnegative pad_dur and whole_dur in decimal seconds or us/ms/s units. Internally these remain integer microseconds until the padding operator's input rate is known. The conversion is nearest sample with halfway cases rounded upward: (microseconds*rate + 500000)/1000000 using bigint. The library exposes the same operation through padDurationMicros/wholeDurationMicros. Negative/infinite durations, colon/quoted clock syntax in filter options and simultaneous length/duration modes remain outside the supported parser scope.

Sample-count, packet-section and buffer-reservation planners now accept the original input rate and propagate asetrate changes in operator order. Duration before asetrate uses the preceding rate; duration after it uses the new rate. Standalone planning without a rate fails explicitly when a nonempty duration-based padding stage needs it. Sample counts exceeding signed64 after conversion fail without allocation. Shared duration parsing lives in avutil and remains re-exported through cli, avoiding a filter-to-CLI layer dependency.

Two hundred forty CLI differential cases cover three source precisions, mono/stereo, 8000/11025 Hz, two I/O budgets and ten duration/FIFO/planar/rate-order/nested chains. Whole framecrc output matches, including 62/63us boundaries, zero and sub-sample durations and minimum duration deficits. Unit tests check rate-sensitive planning and standalone duration options; workerd checks a 625us minimum at 8000 Hz producing five total samples. Resampling composition is described below; infinite padding remains incomplete. The original reviewed FATE set remains five cases.

The expanded differential suite runs its test files serially to avoid concurrent native-process contention in the large frame-limit and conversion matrices. Oracle configuration, comparison assertions and existing per-case timeouts are unchanged.

## Output time selection across padding sections

Finite apad now supports output -ss, -t and -to, including ranges that start or end within added silence, zero output duration and seeks past output EOF. Output selection operates in the final filter sample rate and resets encoded output PTS to zero. It slices every planar channel consistently. Input-side trim remains before the filter chain. Finite resampling composition is described below. Output frame limits and positive durations rounding to zero samples follow the packet schedules below.

The packet-section clipper skips whole sections using bigint counts, preserves the remaining size of the first selected packet, truncates the last section and never enumerates all packets. Framecrc supports a distinct first-packet length in each section. This keeps partial input packets, silence packet boundaries and FIFO-reframed sections correct regardless of physical read size. Work is bounded by the number of graph sections, including offsets beyond number precision. Section metadata is validated before use.

Native comparisons include 128 whole-framecrc cases across signed16/double inputs, mono/stereo, four padding/FIFO/planar/nested chains and eight time profiles. Another 36 WAV/AIFF/AU cases compare explicit-format native decoding byte for byte and verify parsed output rate/channel/sample counts, including empty outputs. Empty AU is decoded with explicit -f au because the native auto-probe rejects its own empty generated header; automatic-probe equivalence is not claimed. Unit tests cover partial-first packets, chained clipping, bigint offsets and malformed sections. Workerd verifies selecting three silent samples from inside a finite tail.

## Output frame limits

Finite apad supports output frame counts, including zero, negative unlimited counts and signed64 maximum. After output seeking and duration clipping, the planner counts the selected semantic packets across section boundaries. A partial first packet counts as one frame; the input tail and each padding tail retain separate boundaries. Counts use bigint arithmetic bounded by the section count, without enumerating packets or allocating silence proportional to the limit.

A positive output duration rounding to zero samples passes the first selected packet, matching the reference; an explicit zero-frame limit still yields empty output. This differs from an explicitly zero duration. Native coverage includes 208 short-fixture whole-framecrc cases across signed16/double, mono/stereo and four FIFO/planar/nested chains, plus 80 multi-packet raw/AIFF cases at 8000/44100 Hz with PCM24 output and bounded physical chunks. Unit tests exercise partial heads, huge counts and malformed metadata; local workerd verifies a two-frame limit after seeking inside a silence packet. This packet-schedule evidence does not certify resampler packet boundaries or infinite padding.

## Finite padding with rate conversion

Finite apad composes with the default automatic FIR rate converter at the negotiated format boundary. The shared count planner applies each padding/FIFO operation and the finite resampler drain in execution order. pad_dur/whole_dur use the rate at that stage, and whole_len uses the actual post-conversion count when downstream. Buffer reservations use the same transformed counts, including zero deficits; they do not reserve the pre-conversion deficit. outputSamples and requiredBufferSamples accept optional {rateBoundary, configuredInput} planning options. packetSections accepts a configured-input flag for finite non-resampling schedules.

The CLI passes known source format metadata into stream processing; an inserted rate converter supplies its negotiated output descriptor. Format conversion and asetrate propagate descriptors without retaining input payloads. padAudio accepts an optional emptyInput descriptor, so downstream apad can generate silence even when the FIR drains to zero samples. Without a descriptor the standalone API retains its original empty-input behavior. Descriptors include the sample origin; generated planar silence retains bounded allocations and exact bigint PTS.

Evidence includes 1800 raw PCM comparisons: signed16/float32/float64, zero/one/21/65/257 input samples, three rate pairs, mono/stereo, ten additional/minimum/count/duration/FIFO/planar/nested chains and signed16/double output. Sample counts match exactly. Double-only paths use absolute error <=2e-12; mixed floating paths <=1e-6; signed16 normalized error <=1e-6 plus one LSB. Another 288 WAV/AIFF/AU cases compare decoded samples and parsed metadata with output seek/duration/stop selection. Seventy-two empty-input non-resampling framecrc cases verify configured padding, planar constraints and packet limits. Local workerd covers padding before resampling and padding after a zero-sample drain.

Finite resampling now supports frame-count limits, framecrc and positive durations rounding to zero through the semantic schedules documented in [resampling](resampling.md#semantic-resampler-packet-schedules). Simultaneous channel remix remains unsupported. Infinite/default padding and general complex filter graphs remain incomplete. Numerical sample comparisons do not establish container byte identity or full filter conformance.

Generated padding on an empty configured CLI source reserves its required silence frames in the aggregate payload plan, even with zero source read buffers. A resident budget smaller than simultaneous generated frames fails before output creation. Physical chunk budgets remain independent of semantic resampler packet lengths.

Save/restore of the finite padding state across fresh runtimes is described in [apad checkpoints](pad-checkpoints.md).
