# Node filesystem adapter

`await createNodeFileSystem({ root, maxReadBytes, maxWriteBytes, overwrite? })` returns the Core VFS interface for local development and conformance runs. Virtual paths are absolute within an existing root. Parent directories must already exist. Traversal components and resolved symlink escapes are rejected. The directory tree is trusted configuration; this adapter is not an OS sandbox against another process racing directory/symlink replacements.

Reads reopen and close the file for every bounded range, so the Core ReadHandle requires no new close method. Each read validates device/inode, size, nanosecond modification time and change time against the opening snapshot, before and after reading. This detects ordinary replacement or modification, not adversarial tampering that restores metadata. Read offsets remain bigint through the Node API. Empty/EOF reads do not perform integrity checks because they return no file data. Cancellation is checked between filesystem operations.

Writes use an exclusive, mode-0600, UUID-named staging file in the destination directory. The caller must await each write and keep its buffer unchanged until completion. Concurrent operations on one output are rejected. A failed write or commit leaves the output in a failed state requiring abort; abort closes and removes the staging file and is retryable if cleanup fails.

Commit syncs and closes the staged file, then publishes it in the same directory. Default publication uses a hard link, so an existing destination (including a competing transaction) causes EEXIST instead of replacement. `overwrite: true` explicitly uses rename replacement. A per-call `openWrite(path, { overwrite })` overrides the adapter default, allowing FFmpeg -n/-y to keep their requested policy. Abort after a successful commit is a no-op. Hard-link/rename support and behavior are provided by the local filesystem; unsupported publication fails explicitly.

A failure removing the staging hard link after publication raises `NodeOutputCommitError` with `published: true`, destination and staging paths. It must not be interpreted as a rolled-back output. Directory fsync, crash recovery and job-state reconciliation are not implemented, so successful publication is not a power-loss durability guarantee. Staging names allow leftover transactions to be identified, but there is no automatic sweeper that might delete another active job's data.

Integration tests cover staged visibility, no-clobber commit races, explicit overwrite, abort cleanup, path checks, bounded reads/writes, cancellation, input replacement and real-file PCM WAV stream copy. The six-codec native WAV differential test now uses this adapter for both input and output. Node support does not establish Cloudflare production compatibility; Core and Workers typechecks exclude this package and dependency checks forbid portable packages from importing it.
