# Audio FATE candidate audit

`npm run fate:audit` reads the explicit FATE inventory and classifies definitions in tests/fate/filter-audio.mak against the current compiled audio-filter parser. It writes compat/reports/fate-audio-candidates.json. The compatibility report runs this gate after generating the inventory, before taking the source snapshot.

The audit verifies the pinned upstream commit and every inventory source hash before inspecting candidates. It records the inventory hash, bundled compiler hash and reviewed profile file hashes. No upstream command, shell fragment, media input or expected result is executed. Only simple whitespace-delimited -af strings without quoting, expansion or shell metacharacters are passed directly to the compiler. Unsupported filters are retained in their original command, never removed to obtain acceptance. Quoted/complex syntax is marked not-analyzed.

Each candidate includes the original target, definition file/logical line, command/helper, external-sample flag, filter text, accepted step names or exact parser rejection, reviewed-profile presence and outstanding review dependencies. A profile being present is deliberately distinct from a fresh passing native/Edge execution. Compiler acceptance does not establish helper equivalence, correct input binding, numerical compatibility or Workers behavior.

The current pinned source has 79 explicit audio definitions: four accepted by the compiler, 41 with unsupported filters and 34 requiring separate syntax/graph review. The four accepted definitions have reviewed execution profiles, including the newly integrated finite apad target. For example, fate-filter-volume additionally requires aperms=random; stripping that operator would change the official test's scope, so it remains unexecuted. Other candidates require input provenance, helper/argv adaptation and expected-result review in addition to implementation work.

The audit does not expand generated Make targets or count the complete upstream FATE suite. Its categories are development triage, not compatibility statuses. The original execution runner continues to require locked generator input, upstream expected bytes, successful original Make target, exact reviewed argv and matching Edge output. The static audit itself claims no passing execution. The separate reviewed apad runner now provides a fifth original FATE execution result.
