# Default audio resampling core

`@edge-ffmpeg/swresample` exports `resampleAudio(frames, outputRate, options)`, `planAudioResample`, `resampleInternalFormat` and `resampledSampleCount`. The streaming library API is also connected to the scoped PCM/G.711 CLI output `-ar` path described below.

The core implements the native default SWR Kaiser-windowed sinc profile independently in TypeScript: filter size 32, cutoff 0.97, beta 9 and exact rational phases with linear interpolation fallback. For input rate I and output rate O, the cutoff factor is min(0.97 O/I, 1), the even tap count is ceil(32/factor) rounded upward to an even integer, and the phase count is O/gcd(I,O). Sinc coefficients use a Kaiser window and all phases are normalized against phase zero. No FFmpeg implementation code, native call or precomputed oracle coefficient table is used at runtime. Coefficients are calculated from these equations.

Accepted library input is packed s16, flt or dbl or planar s16p, fltp or dblp with stable rate, channels and layout, finite samples and contiguous sample-aligned PTS (or consistently unknown PTS). Rates are positive signed32 integers. Exact rational phase tables up to 1024 phases are supported; larger exact phase counts use a 1024-phase table with linear interpolation of adjacent convolution results. The virtual final phase shifts phase zero by one tap with a zero leading coefficient. The plan exposes `interpolates`; no additional phase row is allocated. There is no rematrix, dither, timestamp compensation, alternative filter profile or automatic conversion between library frame formats. `planAudioResample` defaults to dbl and accepts `sampleFormat: 's16'` or `'flt'`; `resampleAudio` infers the format from the first frame unless explicitly specified. Frames must retain that format.

`maxFrameBytes` bounds both input frames and each independently owned output plane. `maxStateBytes` reserves the coefficient bank plus a fixed interleaved history ring of 2*taps+2 sample frames, using two-byte elements for s16, four-byte elements for flt and eight-byte elements for dbl. Coefficients are normalized in double precision before being stored in the selected precision; the float path uses two separately rounded accumulation lanes and a final float sum. The plan rejects oversized state before allocation. It excludes caller input, yielded output, GC/runtime metadata and Wasm; it is not an observed peak-memory guarantee. Long streams do not grow the history ring. Cancellation is checked while building coefficients, reading samples and evaluating FIR output. Consumer-retained output is outside this reservation.

Input is buffered through the initial FIR delay. The beginning reflects around sample zero; finite draining reflects the tail around its half-sample boundary. Very short streams can produce zero or fewer samples than the nominal rate ratio. Draining depends on retained samples and rational phase, so total count is not always ceil(N*O/I). `resampledSampleCount` models this default finite profile, including the 42-sample 48000-to-44100 case yielding 38 samples. Equal rates bypass FIR processing and return independently owned copies.

Output PTS uses an output-sample time base. The first sample-aligned input origin is rescaled with bigint nearest rounding; subsequent output PTS advances by actual samples emitted. Missing PTS remains missing. Output frame boundaries follow the configured byte budget, not native AVFrame partitioning. Discontinuities or format changes fail explicitly.

Differential evidence compares six rate pairs (8000/16000, 44100/48000, 16000-to-44100 and 48000-to-8000), mono/stereo finite fixtures and 1/7/32-sample input partitions. Sample error is checked at an absolute 2e-12 tolerance per fixture, with exact output counts and exact equality across input partitions. Another 480 cases cover 1 through 80 input samples across six rate pairs, checking flush counts and reflected boundary values. Unit tests cover bigint origins, ownership, resource limits and rejection/cancellation; local workerd checks delayed processing and flush on an impulse fixture. These tests establish numerical evidence for the recorded local scalar oracle, not binary identity or general resampling conformance.

Remaining work includes aresample filter syntax, non-default internal formats, arbitrary filter options, compensation and native packet/error semantics, plus canonical-platform and production Workers validation.

## CLI output rate conversion

Actual output `-ar` conversion requires `-cpuflags 0`. Supported integer, floating and G.711 encoders are accepted. All twenty supported PCM/G.711 raw representations and supported WAV/AIFF/AU inputs feed the existing bounded codec paths. The backend uses the default internal-format selection described below, then encodes the resampled samples. All twenty raw representations are supported, subject to container codec restrictions for WAV/AIFF/AU. Channels must remain unchanged. Supported filters are anull, asetnsamples, asetrate and constant fixed/float/double volume. The rate conversion is placed at the negotiated boundary described below, which can precede or occur within the chain. Input seek/duration runs before filtering; output seek/duration selects output-rate samples after draining/resampling. Staged mux output uses the transformed rate and exact selected sample count, including empty short streams.

Native format negotiation can place resampling at an earlier automatic sample-format conversion. Rate conversion combined with rematrix or stream copy remains rejected. Finite rate conversion supports frame-count limits, framecrc and positive sub-sample output durations through the semantic packet schedule described below. Unchanged -ar requests use the existing path. Existing input EOF seek restrictions for raw/WAV remain in force.

The backend preflights FIR coefficient/history state before output creation and subtracts that reservation from the PCM payload budget. Six extra handoff slots cover input conversion, FIR output and negotiated format conversion. FIR output frame size follows the adaptive PCM frame reservation, so reducing input reads to satisfy aggregate budgets also reduces output allocations. A tight-budget test leaves only 200 payload bytes after FIR state and verifies bounded progress without an oversized input/output frame. This remains static payload accounting rather than measured isolate peak memory.

CLI differential evidence covers 64 rate/channel/output-container/timing cases, three double-filter/FIFO/asetrate/input-duration cases and 36 auto-detected container/short-input cases. Samples use the same absolute 2e-12 per-fixture tolerance; output counts and parsed container rate/channel metadata are exact. Five additional rate pairs exercise the interpolation fallback in mono/stereo, including the final table interval, with exact input-partition invariance. Local workerd tests execute both interpolation profiles and CLI resampling into staged R2 WAV output. General CLI resampling conformance and binary floating output identity remain unverified.

Additional float evidence covers twelve exact-rational rate/channel fixtures, 36 interpolation/short-input fixtures, 320 CLI source/target/rate/channel combinations and 18 precision-preserving filter/timing combinations. Float-processing cases use an absolute 1e-6 sample tolerance on the bounded test fixtures, with exact sample counts and exact equality across input partitions. Existing double-to-double cases retain the 2e-12 tolerance. A few native float outputs differ by several ULP, so binary float conformance remains unverified. Separate workerd tests cover float state/interpolation and G.711-to-float AU through staged R2. Non-finite/overflow behavior, arbitrary resampler configuration remains outstanding.

## Fixed signed16 profile and integer output

Default internal precision during rate conversion depends on both endpoint sample formats. This differs from unchanged-rate rematrix selection:

| Source frame format | Destination frame format | FIR format |
|---|---|---|
| dbl | any supported format | dbl |
| u8 | u8 or s16 | s16 |
| s16 | u8 | s16 |
| all remaining combinations | any supported format | flt |

Wire representations map through their codec frame formats: for example, signed8 maps to u8, 24-bit PCM maps to s32, and G.711 maps to s16. In particular, ordinary s16-to-s16 default resampling uses flt internally. `resampleInternalFormat` exposes this selection; direct `resampleAudio` library calls use their explicitly supplied/inferred processing format.

The signed16 FIR quantizes normalized coefficients to clipped Q15 integers with float32 intermediate conversion followed by nearest-even coefficient rounding. Accumulation uses exact integer arithmetic within a checked bound; interpolated accumulator deltas use bigint multiplication/division with truncation toward zero. The final sum adds 16384, divides by 32768 with floor rounding and clips to signed16. Coefficient/history storage uses Int16Array. Internal two-byte samples are included in the backend payload width even for u8-to-u8 endpoints.

Fixed-profile differential tests compare twelve rate/channel fixtures, a stream containing every signed16 value and 32 short-input/boundary fixtures byte for byte against an explicitly forced native s16p resampler. The oracle profile is explicit per test; it does not change the pinned build or claim that default s16-to-s16 selects fixed processing. Default-profile CLI tests additionally cover every u8 codeword and signed16-to-u8 full-domain streams across two rate directions, with exact raw bytes.

The complete raw CLI matrix now covers 1600 combinations (twenty sources, twenty targets, two rate directions and mono/stereo). Counts are exact. Identical encoded output is accepted directly; otherwise both outputs are decoded by native FFmpeg for comparison. The base normalized tolerance is 2e-12 for double-source fixtures or 1e-6 otherwise, plus one destination linear-integer LSB when applicable. G.711 comparisons receive no additional linear quantization allowance. This numerical contract does not certify binary identity for the full matrix.

Another 156 cases compare default integer WAV/AIFF/AU output, rate/channel/count metadata, input/output timing, FIFO, asetrate and integer fixed volume. All 60 u8-source files match native bitexact files; other decoded signed16 fixtures permit one LSB. Workerd checks the fixed interpolation impulse exactly and resamples u8 into default signed16 WAV through staged R2. Tight-budget unit evidence also covers u8 endpoints expanding to signed16 FIR state.

## Mixed-format rate placement planning

`AudioFilterChain.rateBoundary(inputFormat, inputRate, outputRate)` now exposes an immutable automatic rate-conversion boundary for the currently supported linear filter syntax. It returns null if the final rate is already the requested rate. Otherwise it returns `beforeStep` (zero-based, with steps.length meaning after the chain), input/output rate and input/output packed format. Invalid format/rate inputs fail explicitly.

Output rate constraints propagate backward through format-preserving filters. The last asetrate pins its output rate and stops this propagation. If the last negotiated filter format differs from the encoder, conversion remains after the chain. Otherwise the rate conversion can share the last sample-format conversion after that rate constraint. For example, signed16 input with double volume and a double encoder converts rate before volume; adding asetrate after volume moves rate conversion to the output boundary. A dbl-to-flt-to-dbl volume chain converts rate at the second volume's format boundary.

Seven differential cases compare the plan's location and formats/rates to the pinned native verbose filtergraph diagnostics, including the actual automatic-filter insertion destination. This diagnostic comparison verifies planning separately from the execution tests below. The CLI now executes this boundary for the supported linear chain. Internal FIR precision is selected from the boundary input/output formats, then its result converts to the negotiated filter format before the next node. Sample counts are propagated in the same sequence: finite padding/FIFO before the boundary, FIR finite draining, then finite padding/FIFO after it. Input trim precedes the chain and output trim follows it. The planner does not yet cover complex graphs, explicit aresample, channel rematrix constraints or arbitrary filter rate negotiation.

Mixed-format execution evidence covers 120 CLI cases: four source representations, ten filter chains and three destination precisions. Cases include fixed/float/double volume transitions, FIFO before/after conversion, multiple FIFOs, asetrate on either side of precision changes and input/output time limits. Output counts are exact; normalized sample error is at most 1e-6 for floating output, or 1e-6 plus one signed16 LSB for signed16 output. The fixture amplitudes are bounded; these tolerances are not a general bit-exact guarantee. A local workerd case verifies signed16-to-double conversion before volume/FIFO, including 133 samples after padding. Unit checks cover insertion position validation and snapshotting insertion options. Complex graphs, multiple explicitly requested resampling stages and combined channel rematrix remain incomplete.

Additional mixed-format boundary coverage checks 216 CLI cases across signed16/float32/float64 sources, six input lengths (1, 21, 24, 42, 65 and 257), mono/stereo, double/signed16 output and three chains with multiple asetrate constraints and FIFO padding around precision transitions. Exact sample counts include empty and padded short streams. The existing mixed-execution numerical tolerances are retained. Stream-insertion unit tests also verify upstream iterator closure after conversion failure and early consumer return, with no unnecessary extra input reads.

Planar input/output is now supported directly for the three FIR precisions. Processing precision options remain independent of packing; aggregate frame bytes and bounded history are unchanged. See [planar FIR validation and ownership](planar-audio.md#planar-fir-resampling). CLI planar graph negotiation remains incomplete.

Finite apad now composes with this boundary, with per-stage duration rates, post-conversion minimum deficits and configured empty-stream metadata. See [finite padding and rate conversion](audio-padding.md#finite-padding-with-rate-conversion) for the native cases, numerical contracts and remaining packet-scheduling restrictions.

## Semantic resampler packet schedules

The standalone resampleAudio iterator still uses bounded physical frames. The finite CLI now plans native semantic frames separately: cumulative FIR availability per input packet, initial buffering, the first output allocation, non-final overflow drains and final EOF drains. Both drain paths use 4096-sample packets. Input packet spans follow raw/WAV/AU or AIFF semantics; FIFO resets framing and finite apad appends a separate silence run. AudioFilterChain.planSamples exposes immutable per-step counts/rates plus the inserted rate-conversion stage, shared with buffer reservation and packet planning.

Schedules retain bounded runs and cumulative bigint formulas rather than arrays of packet lengths. Queries count frames and clip seeks with binary search, including offsets above number precision. Downsampling runs with zero-output input packets are compressed; high-ratio startup output can split into native allocation-sized output plus 4096-sample drains. framecrc consumes the cumulative schedule while accumulating checksums across small physical chunks, with per-boundary/count/size validation. It does not assemble a whole native packet in memory. Empty configured-source padding now reserves its generated frames even though no source payload is read.

Output frame counts apply after final-rate seek/duration clipping, including partial first frames, zero, negative unlimited counts and very large limits. A positive duration rounded to zero passes the first selected semantic frame; a zero-frame limit remains empty. Stream copy, simultaneous rate/channel conversion, explicit multiple resampling stages, non-default FIR parameters and arbitrary timestamp discontinuities remain outside this scope. Extreme rate ratios requiring native bounded-rational approximation remain unverified.

Native evidence includes 248 packet-plan scenarios across eight rate pairs, startup/short/long inputs and four source spans (including one-sample frames, low-rate downsampling and 1-to-8000 startup overflow). Another 1152 signed16/float32/float64 CLI cases check frame limits/sub-sample timing through finite padding/FIFO/format chains: exact counts, absolute double error <=2e-12 and mixed-float error <=1e-6. Whole framecrc text matches for 384 silent native scenarios under two physical buffer budgets and 144 nonzero fixed-point u8/signed16 cases. The fixed-point cases also catch coefficient values that round differently unless scaled Q15 coefficients first pass through float32. A further 144 WAV/AIFF/AU-input cases validate raw/WAV output sample counts, PCM and WAV headers after scoped input/output seeks. Local workerd verifies nonzero fixed-point framecrc and partial-first/native-tail boundaries. General floating framecrc byte identity is not claimed; numerical FIR agreement does not imply identical checksums.
