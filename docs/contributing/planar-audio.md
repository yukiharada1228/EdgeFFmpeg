# Planar audio conversion core

`convertAudioFrame` accepts packed u8/s16/s32/flt/dbl and planar u8p/s16p/s32p/fltp/dblp. The public `AudioSampleFormat` union contains both `PackedSampleFormat` and `PlanarSampleFormat`. Conversion can change packing and numeric precision in one pass. Rate, channel order/layout, sample count and bigint PTS remain unchanged.

Packed input has one interleaved plane. Planar input has exactly one plane per channel, each containing exactly samples*bytesPerSample bytes. Arbitrary Uint8Array byte offsets are supported. Missing, sparse, mis-sized or extra planes fail validation before output allocation. The required maxFrameBytes bounds the sum of all destination planes, not each channel independently. Input is read in place; no repacked intermediate or full-frame conversion scratch is allocated.

Output owns a new single backing allocation. Planar output planes are disjoint views of that allocation in channel order, so they share backing storage without overlapping byte ranges. No output plane aliases input; callers retaining one output plane can retain the whole allocation. Metadata and PTS follow the existing conversion ownership contract. Per-channel view objects, DataViews, caller-owned input and garbage-collector retention are outside the payload-byte budget. Cancellation is checked during plane validation and sample conversion.

Identical numeric precision copies sample bytes directly while rearranging layout, preserving signed zero, infinities and NaN payload bits. Other conversions retain the scalar integer-depth, clipping and nearest-even rules documented in sample-format-conversion.md. Cross-precision NaNs and non-finite/out-of-profile float-to-integer values remain rejected.

Linear PCM encodePcm can consume planar frames through its existing conversion-to-native path. General filter processing still has its documented packed frame requirements; planar conversion is not automatically enabled throughout the CLI. The aformat CLI parser still rejects planar constraints pending graph-wide planar negotiation. The core does not imply planar codec wire formats or native AVFrame padding/linesize compatibility.

Differential evidence covers 75 source/target/channel combinations (five numeric formats each, with 1/2/6 channels). Each uses packed/planar source and packed/planar destination variants, compared to a native scalar graph with explicit planar constraints. All 300 variant outputs match packed native PCM bytes, and every destination plane is independently checked against native channel positions. Unit tests cover asymmetric channel values, non-overlapping ownership, total frame budget, subviews, exceptional floating payloads, sparse planes, cancellation and cross-precision NaN rejection. A local workerd test converts s16 to dblp and back and encodes big-endian linear PCM with exact PTS and bytes. Full pipeline planar support, arbitrary numeric domains and production runtime conformance remain unverified.

G.711 encoding also accepts planar input through conversion. Signed16 planar input now has a direct channel-read path: no interleaved signed16 scratch is allocated, and maxFrameBytes only needs to fit the resulting one-byte-per-sample coded packet, matching the existing packed-s16 path. Each input plane is validated, including sparse arrays and nonzero byte offsets; ownership stays with the caller. Other numeric formats still require the bounded signed16 conversion intermediate. Six strict native cases cover all signed16 values per channel across mono/stereo/six-channel asymmetric fixtures for A-law and mu-law. A workerd fixture validates exact bytes and bigint PTS with an output budget too small for a packed signed16 copy. General pipeline planar support remains incomplete.

## Planar FIFO reframing

`reframeAudio` now accepts all five planar formats directly. Each channel is copied into its disjoint portion of a single bounded FIFO allocation, without interleaving scratch. Both input and output frame limits apply to aggregate bytes across channels. Every planar input must have exactly one correctly sized plane per channel. Sample format, channel layout, rate and timestamp continuity remain stable across frames. Padding fills every u8p channel with 128 and other formats with zero. No-padding final output exposes only the actual samples of each channel, while its views can retain the full FIFO allocation. Each yielded frame owns fresh backing storage and remains unchanged while later output is produced.

Thirty native precision/channel/padding cases (five formats, mono/stereo/six channels and both padding modes) are run under 1/5/23-sample input partitions, for 90 variant executions. Repacked output bytes match explicit native planar asetnsamples graphs exactly, and output sample timestamps use a bigint origin beyond number precision. Unit tests check aggregate limits, sparse/misaligned planes, per-channel silence, no-padding tails and early upstream closure/backpressure. Local workerd exercises a six-byte two-channel FIFO with exact planes and PTS. This expands the standalone FIFO API; aformat CLI planar constraints and general planar filter negotiation are still outstanding.

## Planar FIR resampling

`resampleAudio` now accepts s16p/fltp/dblp frames and retains their planar layout in output. The sampleFormat option on the FIR plan still specifies processing precision (s16/flt/dbl), independent of packing. Stable planar layout is inferred from the first input and cannot change midstream. Each input channel plane must contain exactly samples*bytesPerSample bytes. maxFrameBytes limits aggregate input and output plane bytes. Input is read channel by channel directly into the existing bounded FIR history ring; no packed input scratch is allocated.

Planar output uses disjoint channel views of one new frame allocation. A short final frame exposes only its actual samples per channel, with offsets based on the full allocated frame capacity. The retained allocation can therefore be larger than the sum of final plane lengths, but remains within maxFrameBytes. FIR coefficient/history state accounting and cancellation are unchanged. Equal-rate bypass makes owned planar copies. Non-finite samples, sparse/malformed planes, non-contiguous PTS and layout changes fail explicitly.

Fifty-four native cases cover three FIR precisions, mono/stereo/six channels, exact-rational/interpolated rate pairs and three short/long input lengths, each under 1/7/16-sample partitions (162 variants). Repacked output matches forced native planar processing: exact bytes for signed16, absolute tolerance 1e-6 for float32 and 2e-12 for float64. Counts and input-partition invariance are exact. Unit tests cover aggregate limits, ownership, equal-rate bypass, large PTS, sparse planes, non-finite secondary channels and packing changes. Local workerd checks opposite-sign stereo planar impulses with exact count and numerical samples. General CLI planar negotiation, complex graphs and combined channel remix remain outstanding.

## Planar mono/stereo rematrix

`remixAudioFrame` accepts all ten packed/planar sample formats and can emit either packing. `remixInternalFormat` now selects precision independently of packing: dblp retains dbl internal arithmetic, and u8p/s16p select the same fixed/float profiles as their packed equivalents. The existing canonical mono/stereo layout restrictions, integer-versus-floating destination normalization and explicit separate/fused arithmetic profiles remain unchanged.

Input is converted to the selected internal precision while retaining source packing, then read directly from its packed plane or channel planes. The mixed result is written in destination packing without an interleaving scratch. A final numeric conversion is performed when the requested destination precision differs from internal precision. Each conversion/output allocation must fit maxFrameBytes in aggregate. Multiple handoff buffers can coexist; the option is not a total resident-memory guarantee. Output channel views are disjoint and independently owned from input; input/output precision arrays may share their own frame's backing allocation.

Fifty source/target/direction combinations (five precisions and both channel directions) each run four source/destination packing variants, for 200 strict native PCM comparisons. Native input is explicitly constrained planar; the known scalar contraction profile is selected explicitly by the test helper. Equal-rate remixing does not imply resampling/rematrix composition compatibility. Unit tests cover precision selection, fixed rounding, PTS, same-channel packing conversion, signed zero, sparse planes and aggregate upmix limits. Local workerd verifies planar downmix and upmix with exact samples and bigint timestamps. General multichannel layouts, custom matrices, non-finite remix samples, combined rate/channel conversion and CLI planar negotiation remain incomplete.

## Planar input to linear filters

The existing compiled filter chain now accepts all five planar input formats. Anull and asetrate preserve layout and reference the input planes; FIFO uses its direct planar storage. Aformat with a packed constraint and constant volume convert through the existing packed precision negotiation. Volume output currently uses packed storage even when the input is planar. This library entry-point support does not enable planar aformat constraints or CLI graph-wide format selection.

Validation checks plane count, each channel's exact size, sparse arrays and aggregate frame bytes before processing. Mixed packed/planar transitions happen at defined conversion operators; stateful FIFO still rejects unexplained layout/format changes. Ninety native cases compare five planar source precisions, mono/stereo/six channels and six anull/asetrate/fixed-float-double volume/FIFO/aformat chains. Final signed16 samples match byte for byte, with exact counts and sample PTS. Unit tests verify metadata-only aliasing, owned packed volume output, aggregate limits and sparse-plane rejection. Workerd runs a planar asetrate/FIFO/fixed-volume chain within a twelve-byte frame budget and verifies output samples plus bigint PTS. Planar output constraints, complex filter graphs, global format negotiation and production conformance remain outstanding.

## CLI integration

Singleton planar aformat constraints now participate in the supported CLI linear graph. Rate-boundary metadata includes packing; internal FIR precision normalizes it away. Output time trimming slices all channel planes, and final PCM/G.711 encoding writes existing supported wire formats. Native numerical/byte comparisons and the workerd packing-dependent rate-placement case are detailed in [aformat CLI support](aformat.md#cli-planar-constraints). Earlier sections describe the library-level building blocks; their former CLI planar limitations are superseded for this scoped singleton graph path. Preference lists, complex graphs and unrestricted negotiation remain outstanding.
