# Scoped FLAC CLI copy evidence

Production: `openFlacDemux` -> bounded borrowed chunks -> incremental zero-seed Adler-32 -> framecrc, using output-policy and OutputGroup preparation/publication. No Node/native/private prototype imports. STREAMINFO extradata is serialized before software and stream headers. Audio packet boundaries are demux boundaries, independent of payload read sizes. Every chunk is released in a finally block. Existing parser CRC validation is retained.

Attribution: scoped adaptations from FFmpeg 9.0.2 commit `946fcce07b6dcd0331c8cc609192aeff5e1924f8`, LGPL-2.1-or-later: libavformat/framecrcenc.c and framehash.c (Fabrice Bellard), fftools/ffmpeg_mux_init.c and ffmpeg_opt.c. Repository upstream source and license notices remain authoritative. `cases.json` pins the freshly executed reference binary SHA-256 and version. `generate.mjs` is development-only and executes Native children sequentially. The fixture is newly encoded deterministic mono PCM, with a title tag, rather than reused packet expectations.

Finite clean evidence covers magic detection with extension-independent input, explicit `-f flac`, audio maps, duplicate audio maps, frame limits including zero, bitexact, overwrite refusal/replacement, cancellation and failed write cleanup. Unit checks exercise seven-byte short reads and 34-byte writes. Integration executes the actual Node launcher and checks publication without staging residue. A separate browser-platform bundle verifies the production copy dependency graph has no Node/native imports. This does not certify a Workers deployment or aggregate runtime accounting.

The shared CLI parser forwards `-metadata` and `-map_metadata` to the selected backend. The metadata fixture is exercised through the actual launcher: `-metadata key=value` and `-map_metadata 0/-1` do not affect framecrc headers/packets, matching Native. Other metadata scopes and general metadata/chapter mapping remain unsupported. Native missing-stream/no-audio failures are stored independently and compared for exit status, not exact log text.

Supported selection is one FLAC input and one explicit framecrc output with copied audio. Automatic selection includes attached pictures, so those inputs fail explicitly unless audio is mapped or `-vn` excludes pictures. Positive/negative and optional audio maps are supported, with up to 64 duplicate audio streams; every selected stream must resolve to copy after ordered codec options. Duplicate-map frame limits are explicitly rejected pending per-stream scheduling. Input format declarations override magic; filename extensions do not identify FLAC. Auto detection is currently dispatched for copy requests with explicit framecrc output; raw frame FLAC requires explicit input format and still lacks the STREAMINFO required by this copy route.

Remaining gaps: FLAC muxing/remuxing, other output muxers, decode/encode integration, probe/ffprobe CLI, raw frame input copy, selected attached-picture serialization and image decoding, multiple inputs/outputs, seeking and time clipping, timestamp/global copyts policy, per-stream duplicate limits, additional stream specifiers/dispositions, general metadata and chapter mapping, diagnostics/xerror/explode policy, full AVIO partial scheduling and timestamp parity. Malformed/junk packet flags/side data and provisional layout changes from frame headers are not characterized by these clean fixtures. Malformed metadata and corrupt/truncated frames can differ from Native policy; no broad malformed parity is claimed and CRC checks have not been disabled. Accounted buffers do not establish total JS heap/provider memory, elapsed CPU enforcement, distributed recovery, or full conformance. See the detailed development design acceptance gates and the demux corpus limitations.

The fresh `optional-video-fallback` Native row pins `-map 0:v?` on the audio-only fixture: unmatched optional maps leave automatic selection active. The fresh `optional-negative-fallback` and `optional-negative-then-positive` rows pin negative-map behavior: negatives disable only previously defined positive entries, and an optional negative with no entries preserves automatic selection. Disabled positive entries still suppress automatic selection. `probeFlacInput` returns the exact opened handle (including explicit FLAC declarations); dispatch must pass that handle into `executeFlacCopy` to preserve input generation identity. Direct tests cover changing handles across opens, stalled open/read cancellation with late rejection observation, and caller mutation of framecrc primitive options during writes. STREAMINFO scratch is Core-owned and released on success and failure.

The executor captures the source size and binds its read capability before demux metadata awaits, so replacement of provider properties cannot change STREAMINFO serialization independently of packet reads. Public dispatch regression tests also mutate codec policy and output paths during opening; dispatch snapshots the request before probing and retains the probe handle.
